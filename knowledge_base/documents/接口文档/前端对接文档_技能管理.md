# 技能管理 - 前端对接文档

## 一、核心概念

技能（Skill）是平台的可复用能力单元，每个技能对应 `skills/<skill_id>/` 目录（含 `SKILL.md`、`_meta.json`、实现脚本）。Agent 通过 `tools.json` 里的 `enabled_skills` 启用技能。

**技能状态（`status`）：**
| 取值 | 含义 |
|------|------|
| `active` | 已被至少一个 Agent 引用（在某个 `tools.json` 的 `enabled_skills` 里） |
| `available` | 已安装但未被任何 Agent 引用 |

**技能分类：** 后端内置了 31 个技能的 `SKILL_CATEGORY_MAP`（数据库/数据分析/内容处理/文件处理/网络工具/系统工具/生活工具/媒体工具），每个技能带 `icon` / `category` / `iconBg`。未内置的技能归为"其他"（`🔧` 灰底）。

## 二、技能管理接口

### 2.1 获取技能列表

**GET** `/api/skills`

**响应示例：**
```json
{
  "success": true,
  "data": {
    "skills": [
      {
        "id": "file_manager",
        "name": "文件管理",
        "icon": "📁",
        "iconBg": "linear-gradient(135deg, #f59e0b, #d97706)",
        "category": "文件处理",
        "status": "active",
        "description": "管理项目文件，支持增删改查",
        "version": "1.0.0",
        "author": "",
        "agentsUsing": [
          { "id": "default", "name": "默认助手", "icon": "🤖" },
          { "id": "kunming", "name": "昆明电网助手", "icon": "⚡" }
        ],
        "parameters": [
          { "name": "path", "type": "string", "required": true, "description": "文件路径" }
        ],
        "triggers": ["文件管理", "帮我管理文件"]
      },
      {
        "id": "weather",
        "name": "Weather",
        "icon": "🌤️",
        "iconBg": "linear-gradient(135deg, #8b5cf6, #6d28d9)",
        "category": "生活工具",
        "status": "available",
        "description": "天气查询",
        "version": "1.0.0",
        "author": "",
        "agentsUsing": []
      }
    ],
    "total": 2
  }
}
```

**字段说明：**
| 字段 | 类型 | 说明 |
|------|------|------|
| id | string | 技能唯一标识 |
| name | string | 展示名（来自 `_meta.json` / `SKILL.md` frontmatter，缺省用 id 转可读名） |
| icon | string | 分类图标 emoji |
| iconBg | string | 分类渐变色 |
| category | string | 分类名 |
| status | string | `active`（被引用）/ `available`（未引用） |
| description | string | 描述（缺省自动生成） |
| version | string | 版本号，默认 `1.0.0` |
| author | string | 作者 |
| agentsUsing | array | 使用该技能的 Agent 列表（`id`/`name`/`icon`）；`available` 时为 `[]` |
| parameters | array \| 缺省 | 参数定义（`name`/`type`/`required`/`description`），仅 `_meta.json` 有 `parameters.properties` 时出现 |
| triggers | array \| 缺省 | 触发词列表，仅 `SKILL.md` frontmatter 有 `triggers` 时出现 |

**说明：**
- 列表是**实时扫描文件系统**生成的，无缓存，每次请求都会重新扫描 `skills/` 与 `agents/*/tools.json`；
- 所以前端**无需刷新缓存**，直接重新请求即可拿到最新。

### 2.2 重新加载技能（健康检查）

**POST** `/api/skills/reload`

**响应示例：**
```json
{
  "success": true,
  "message": "技能已重新加载",
  "data": {
    "installed_count": 28,
    "active_count": 12
  }
}
```

**说明：**
- 技能系统是无状态的（`list_skills` 每次都实时扫描），所以 `reload` 主要起到健康检查 + 扫描验证作用；
- 权限：需要 `write` 等级；
- 前端一般不需要主动调用，除非想验证"技能目录当前能扫出几个"。

### 2.3 搜索外部技能（ClawHub）

**GET** `/api/skills/search?q=<关键词>`

**说明：**
- 通过 ClawHub 搜索可安装的外部技能；
- 纯查询接口，不写盘、不安装；
- 前端可在"技能市场"页使用。

## 三、前端页面实现建议

```
技能管理页
├── 技能列表（2.1）
│   ├── 分类分组（数据库/数据分析/.../其他）
│   ├── 技能卡片：icon + name + status 标签
│   ├── agentsUsing：被哪些 Agent 使用（active） / 未使用（available）
│   └── 参数展示（parameters）/ 触发词（triggers）
├── 重新加载按钮（2.2）
└── 技能市场 Tab（2.3）：搜索 + 展示外部技能
```

**交互流程：**
1. 进入页面 → `GET /api/skills` 渲染，按 `category` 分组，`status` 打标签；
2. "使用该技能的 Agent" 用 `agentsUsing` 渲染；
3. 需验证扫描时点 `POST /api/skills/reload`；
4. 市场搜索输入关键词 → `GET /api/skills/search?q=`。

## 六、注意事项

1. **列表实时扫描、无缓存**：`GET /api/skills` 每次全量扫描文件系统，数据量大时可能稍慢；前端可做节流。

2. **`status` 区分"被引用"与"已安装"**：
   - `active` = 至少一个 Agent 在 `tools.json` 里启用了它；
   - `available` = 装了但没 Agent 用。
   - 前端别把 `available` 当成"出错"，它只是"还没被分配"。

3. **图标/分类是后端内置映射**：前端直接用返回的 `icon`/`iconBg`/`category` 渲染，**不要自己映射**，否则新增技能会显示错误分类。

4. **权限**：列表（GET）/ 搜索（GET）仅需登录；重新加载（POST）需要 `write` 等级。
