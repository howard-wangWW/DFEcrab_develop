# 电力系统专家 - 重过载数据查询技能

## 技能名称
`get-http`

## 描述
该技能用于调用电力系统重过载数据接口，查询馈线或配变的重过载情况：
- **馈线重过载数据**（`getFdOverloadData`）
- **配变重过载数据**（`getPbOverloadData`）

接口服务地址：
- 服务器地址：172.20.42.72:8080
- 接口基础路径：`/database`

## 使用场景
- 调度员需要查看某时段内馈线/线路的重载、过载情况
- 运维人员需要分析配变/变压器的负载率异常
- 管理人员需要统计重过载设备分布及风险等级

## 指令示例
用户可说出如下指令：
- "查询今天馈线重过载数据"
- "查一下昨天配变过载情况"
- "最近7天线路重载有哪些"
- "看看本周变压器负载率高的"
- "2025-09-23的馈线重过载数据"
- "五华供电局的重过载设备"
- "查询重过载数据" -> 默认查询最近24小时，需确认是馈线还是配变

## 参数说明

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `query_type` | string | ✅ | 查询类型：`feeder`(馈线) 或 `transformer`(配变) |
| `time_desc` | string | ❌ | 时间描述，如"今天"、"昨天"、"最近7天"、"2025-09-23" |
| `start_date` | string | ❌ | 直接指定开始时间，格式 `YYYY-MM-DD HH:mm:ss` |
| `end_date` | string | ❌ | 直接指定结束时间，格式 `YYYY-MM-DD HH:mm:ss` |

> **优先级**：如果提供了 `start_date` 和 `end_date`，则直接使用；否则根据 `time_desc` 智能推断。未提供时默认查询**最近24小时**。

## 时间推断规则

| 用户说法 | 推断结果 |
|---------|---------|
| 未提及 / 空 | 最近24小时（当前时间往前推24小时） |
| "今天" | 当天 00:00:00 ~ 当前时间 |
| "昨天" | 昨天 00:00:00 ~ 23:59:59 |
| "最近7天" / "本周" | 往前推7天 ~ 当前时间 |
| "最近30天" / "本月" | 往前推30天 ~ 当前时间 |
| "2025-09-23" | 当天 00:00:00 ~ 23:59:59 |
| "2025-09-23 14:00:00" | 指定时间 ~ 当前时间 |

## 接口详情

### 认证方式
两个接口均使用 **Bearer Token** 认证，请求头统一包含：
- `Authorization: Bearer <token>`
- `Content-Type: application/json`
- `Origin: http://localhost:8090`
- `Referer: http://localhost:8090/`

### 1. 馈线重过载接口
- **URL**：`http://172.20.42.72:8080/database/getFdOverloadData`
- **方法**：POST
- **请求体**：
  ```json
  {
    "startDate": "2026-05-15 00:00:00",
    "endDate": "2026-05-15 23:59:59",
    "dataType": "",
    "start": "",
    "limit": "",
    "typeFlag": 1
  }
  ```

### 2. 配变重过载接口
- **URL**：`http://172.20.42.72:8080/database/getPbOverloadData`
- **方法**：POST
- **请求体**（与馈线接口完全一致）：
  ```json
  {
    "startDate": "2026-05-15 00:00:00",
    "endDate": "2026-05-15 23:59:59",
    "dataType": "",
    "start": "",
    "limit": "",
    "typeFlag": 1
  }
  ```

> 注意：两个接口的请求体结构已统一，均包含 `startDate`、`endDate`、`dataType`、`start`、`limit`、`typeFlag` 六个字段。

## 风险分级标准

| 级别 | 负载率范围 | 标识 | 说明 |
|------|-----------|------|------|
| 严重过载 | ≥ 120% | 🔴 | 需立即处理 |
| 过载 | 100% ~ 120% | 🟠 | 需关注并安排处理 |
| 重载 | 80% ~ 100% | 🟡 | 需持续监视 |
| 正常 | < 80% | 🟢 | 运行正常 |

## 实现细节
- 底层使用 `requests` 库发送 HTTP POST 请求
- 认证方式升级为 **Bearer Token**（替代原有的 `api-key`）
- 馈线和配变接口使用相同的请求体结构
- 时间参数通过智能推断模块自动解析用户语义
- 查询结果以标准 JSON 格式返回，包含风险统计摘要

## 注意事项
- 执行前请确保网络可达 `172.20.42.72:8080`
- Token 认证已内置到代码中，有失效期限
- 大量数据查询建议缩小时间范围以提高响应速度
- 返回数据按发生时间排序，RN 字段为行号
