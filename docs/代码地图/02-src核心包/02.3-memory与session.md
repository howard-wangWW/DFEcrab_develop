### 🔴 1.3 `memory/legacy_manager.py` — 空类（4 行）

```python
"""Memory Manager - Stub"""
class MemoryManager: pass
_instance = MemoryManager()
def get_memory_manager(): return _instance
```

| 项 | 内容 |
|---|---|
| 类型 | **空类 STUB** |
| 规模 | 4 行 |
| 问题 | `src/memory/__init__.py:34` 把 `MemoryManager` 名字**指向了这个空类** |

> ### 🔴 已确认的陷阱
>
> `src/memory/__init__.py` 中的映射：
> ```python
> if name == "MemoryManager":
>     from src.memory.legacy_manager import MemoryManager   # ← 4 行空类
>     return MemoryManager
> if name == "LongTermMemoryManager":
>     from src.memory.long_term import MemoryManager as LongTermMemoryManager   # ← 410 行真实现
>     return LongTermMemoryManager
> ```
>
> **后果**：`from src.memory import MemoryManager` 拿到的是一个**什么方法都没有的空类**。任何 `MemoryManager(agent_id=...)` 都会 `TypeError`，任何 `.add_to_long_term()` 都会 `AttributeError`。
>
> **而 `loop.py` 是安全的**——它写的是 `from src.memory.long_term import MemoryManager`（直接走子模块），拿到的是真实现。
>
> **建议**：`legacy_manager.py` 已无存在必要，删除它，并把 `src/memory/__init__.py` 的 `MemoryManager` 直接指向 `long_term.MemoryManager`，或统一改名为 `LongTermMemoryManager`。

**文件头 docstring 描述的架构：**

```
用户请求 → Gateway 检查 session_id
          ├─ 有 session_id → 复用现有会话
          └─ 无 session_id → 创建新会话 → 调用 LLM 生成摘要

Manager Agent 接收：message / session_id / session_history / session_summary
```

| 关键行为 | 说明 |
|---|---|

| **消息懒加载** | `get_messages()` 与 `_load_messages_for_session()` 分离；`session_to_dict(session, load_messages=True)` 可控制是否加载消息 |
| **过期标记** | `_mark_expired_if_needed()` 惰性标记过期，而非定时任务 |
| **历史传递** | 把最近 N 条消息作为 `session_history` 传给 Manager Agent |
| **Agent ID 归一化** | 依赖 `normalize_agent_id`（default → dfecrab） |
| **持久化** | 落盘到 `data/sessions/`（实测 260 个 json 文件） |

| 备注 | 会话数据按 session 分文件存储在 `data/sessions/`；`list_sessions(limit, user_id, include_empty)` 支持按用户过滤（配合 `PermissionService` 的 data_scope） |
