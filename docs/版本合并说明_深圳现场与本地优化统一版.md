## 1. 合并背景与目标

两个代码库同源分叉，各自在不同方向演进。目标是产出一个既能满足深圳现场运行、又包含本地全部优化能力的统一版本。

合并后要求：

1. 深圳现场的全部功能、配置、数据、插件、技能均不丢失；
2. 本地版的架构重构与性能优化全部生效；
3. 合并结果可直接运行，不引入新的运行期错误。

---

## 2. 两版差异全貌

统计口径：仅对比源码类文件（`.py/.json/.yaml/.sh/.proto/.html/.txt/.md/.bak`），排除 `node_modules`、`__pycache__`、`venv`、`.git` 等。

| 维度 | 数量 |
|---|---|
| 深圳版文件 | 579（已排除 `src/alert_judge` 下 4690 个 JSON 数据） |
| 本地版文件 | 487 |
| 两边内容完全相同 | 344 |
| 两边内容不同 | 63 |
| 仅深圳有 | 172 |
| 仅本地有 | 80 |

**结论**：属于"同源分叉"而非"新旧关系"——两边各有对方没有的功能，必须双向合并。

### 2.1 双方各自的主要成果

| 领域 | 更强的一方 | 具体内容 |
|---|---|---|
| Gateway 架构 | 本地 | 深圳 6176 行单体 `grpc_server.py` → 本地拆为 `chat/*`、`lifecycle/*`、`routes.py`、`agent_domain.py` 等 mixin（薄壳 224 行） |
| 任务系统 | 本地 | `task/api_routes.py` 覆盖深圳全部 V2 路由，并多出 pause/resume/trigger/preview/approve/schedule |
| 检索性能 | 本地 | 关键词倒排索引、IVF 向量索引、候选放大与同文档限流 |
| 反思闭环 | 本地 | lessons 取最近条目、写入去重、assessment 注入、评分锚点 |
| 用量统计 | 本地 | MCP 调用埋点、`usage_store`、`daily_stats`、图片生成 |

## 3. 合并策略

```
以「深圳现场版」为资源基线（全量拷贝，保证现场数据与配置零丢失）
        │
        ├─ Gateway 层  → 采用「本地重构版」（mixin 拆分），补深圳独有接线
        ├─ Task 层     → 采用「本地超集版」
        ├─ Knowledge 层→ 采用「深圳版」，融入本地检索/索引优化
        ├─ Files/Session/Skill 层 → 采用「深圳版」
        ├─ Agent/Memory/MCP 层    → 采用「本地优化版」
        ├─ 配置文件    → 双向融合
        └─ 纯深圳独有 / 纯本地独有 → 全部保留
```

基线选择依据：深圳版资源完整（插件、沙箱、现场 LLM 配置、现场数据），且是现场验证过的；在其之上用本地代码层做替换/融合，可最大程度降低现场风险。

### 4.4 重建的文件（2 个）

**背景**：本地版 `src/knowledge/core/` 下这两个模块**只有 `cpython-311` 字节码缓存，源码缺失**（`.py` 不存在），但本地 `retriever.py` 在模块级 import 它们——不重建则整个知识库无法启动（`ImportError`）。

| 文件 | 重建依据 | 对外契约 |
|---|---|---|
| `src/knowledge/core/keyword_index.py` | 从 `keyword_index.cpython-311.pyc` 提取类结构、方法名、属性名、docstring、常量（`_MEANINGLESS_RE`、`_K1`、`_B`、`max_df_ratio`、`max_scan_postings`、`array('i')` 倒排表等） | `KeywordIndex(tokenizer, max_df_ratio, max_scan_postings)`；方法 `is_built()` / `ensure_built(texts)` / `build(texts)` / `search(query, top_k) -> List[Tuple[int, float]]` / `stats() -> Dict`；模块级 `search_scan(texts, tokenizer, query, top_k)` |
| `src/knowledge/core/ranking.py` | 从 `ranking.cpython-311.pyc` 提取函数名、参数、`metadata.doc_id` 处理逻辑、异常类型 | `compute_fetch_k(top_k, max_per_doc, overfetch) -> int`；`diversify_by_doc(ranked, max_per_doc, top_k=None) -> List[Dict]` |

**⚠ 建议**：这两个文件请用你本地原始源码替换核对一次。当前重建实现的功能与参数语义均对齐调用方，但内部实现细节（如 BM25 的具体打分公式、剪枝边界）可能与原版存在差异。

## 6. 已知问题与待确认项

### 6.1 附件注入粒度差异（未强行统一）
