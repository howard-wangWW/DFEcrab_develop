## 二、优化了哪些（问题 → 修复）

| # | 原问题（修复前） | 修复后 |
| --- | --- | --- |
| 1 | **双路由**：`HTTPServer.__init__` 与 `grpc_server` 各注册一套同名任务路由，先注册者胜出 → 网关里那套是死代码；且旧 `api_routes` 每个请求 `TaskManager()` 新建实例，反复重读全部任务文件、内存态与网关不一致 | 路由收口到 `src/task/api_routes.get_task_routes()`，网关只做一次注册；`get_task_manager()/get_periodic_scheduler()/get_task_scheduler()` 全局单例，内存态唯一 |
| 2 | `POST /api/v2/tasks/{id}/convert` 调用了**不存在**的 `TaskManager.update_task` → 永远失败 | 实现 `convert_task`：新建目标类型任务、原任务置 `converted`、周期任务自动注册调度 |
| 3 | `GET /api/tasks/todos*`、`POST /api/tasks/todos`、`GET /api/tasks/stats` 调用 TaskManager 上**不存在**的待办方法 → 永远失败 | 迁移到真实 `TaskScheduler`（持久化 `todos.json`），待办 CRUD/统计可用 |
| 4 | `GET /api/tasks/heartbeats`、`GET /api/tasks/scheduled` 调用空壳 `PeriodicScheduler`（无 `get_stats/list_tasks`）→ 恒失败；周期任务"注册成功"是假象 | 调度器真实实现：5 字段 cron 解析 + 固定间隔、到期触发回调、暂停/恢复、重启恢复、失败记录 `last_error` |
| 5 | `DELETE /api/v2/tasks/{id}` 删除成功后误调 stub 方法抛异常 → **删除成功却返回 400** | 删除语义修复：不存在→`success:false`；删除成功→清理定时作业与审计文件；幂等可重试 |
| 6 | `task_v2_handler` 引用不存在的 `src.task.audit.AuditLogger`、`supervisor.audit_logger/progress_tracker/get_dashboard_data/coordinate_task` → `/audit`、`/dashboard`、`/execute` 三条链路必崩 | 全部补齐；旧 handler 文件删除 |
| 7 | `GET /{id}/audit` 按文件名 glob 找审计文件，而磁盘上是**会话**审计 → 永远为空 | 新增任务级 `AuditLogger`：create/approve/reject/execute/step_*/agent_* 全埋点 |
| 8 | 三方契约漂移（api_routes 返回 `{success,data}`、网关部分端点返回顶层字段、文档又一套） | 统一 `{success, data}` + 关键接口保留旧顶层字段（`tasks/count/progress/audits/stats`），前端无需改版 |
| 9 | 待办 ID 用纯微秒时间戳，快速连续创建会同微秒碰撞**互相覆盖** | ID 加随机后缀（`todo_<ts>_<uuid8>`） |
| 10 | 无新依赖要求 | cron 解析自研（标准库），`requirements.txt` 零变更 |

## 三、接口文档（任务域 20 条路由）

### 0. 通用约定

- Base：`http://<网关>:6789`（所有路径可加 `/dfecrab` 前缀，等价）
- 必带头：`X-User-Id: <账号>`（缺省按 `guest`）；写接口（POST/DELETE）需要 `user`/`admin` 角色，`guest` 返回 HTTP 403
- 响应：成功/业务失败均 HTTP 200，用 `success` 区分

```jsonc
{ "success": true,  "data": { ... } }         // 成功
{ "success": false, "error": "错误描述" }      // 业务失败（HTTP 200）
```

枚举值：

- `task_type`：`simple` / `complex` / `temporary` / `periodic` / `scheduled` / `triggered`
- `status`：`draft` / `pending` / `running` / `completed` / `failed` / `cancelled` / `paused` / `pending_approval` / `converted`
- 待办 `priority`：`1=low` `2=normal` `3=high` `4=critical`（待办状态：`pending/running/completed/failed`）

### 3.1 创建任务

`POST /api/v2/tasks`

| 字段 | 类型 | 必填 | 默认 | 说明 |
| --- | --- | --- | --- | --- |
| `topic`（或 `title`） | string | **是** | - | 任务主题 |
| `agent_group_config` | object | **是** | - | `{"members":[{"agent_id":"dfecrab","role":"analyst"}]}` |
| `task_type` | string | 否 | `temporary` | 见枚举 |
| `description` | string | 否 | `""` | 任务描述 |
| `supervisor_agent_id` | string | 否 | `supervisor_01` | 监管智能体 |
| `execution_mode` | string | 否 | `auto_select` | `auto_select`=Manager LLM 推荐智能体；`manual`=用 `selected_agents` |
| `selected_agents` | string[] | 否 | - | `manual` 模式的智能体列表 |
| `collaboration_mode` | string | 否 | `sequential` | `sequential/parallel/hybrid` |
| `schedule` | object | 否 | - | 周期任务：`{"cron":"0 9 * * 1"}` 或 `{"interval_seconds":3600}`，可加 `timezone` |
| `require_confirmation` | bool | 否 | `true` | `true`=创建后为 `draft`，需 `/approve` 确认 |
| `retry_config` / `notification_config` / `trigger_config` | object | 否 | - | 透传保存 |
| `parent_task_id` | string | 否 | `""` | 父任务（转化场景自动填） |

```bash
curl -X POST http://172.20.51.153:6789/api/v2/tasks \
  -H "Content-Type: application/json" -H "X-User-Id: admin" \
  -d '{
    "topic": "分析电网故障",
    "task_type": "temporary",
    "description": "分析最近的电网故障原因",
    "execution_mode": "manual",
    "selected_agents": ["dfecrab"],
    "agent_group_config": {"members": [{"agent_id": "dfecrab", "role": "analyst"}]}
  }'
```

响应：

```json
{
  "success": true,
  "data": {
    "task_id": "task_20260920103045_ab12cd",
    "topic": "分析电网故障",
    "title": "分析电网故障",
    "task_type": "temporary",
    "status": "draft",
    "supervisor_session_id": "",
    "supervisor_agent_id": "supervisor_01",
    "agent_group": { "task_id": "task_...", "task_type": "temporary", "members": [ { "agent_id": "dfecrab", "role": "analyst" } ] },
    "manager_recommendation": null,
    "available_agents": [ { "agent_id": "dfecrab", "name": "DFEcrab" } ],
    "approval_url": "/api/v2/tasks/task_.../approve",
    "task": { "task_id": "task_...", "status": "draft", "steps": [ ... ] }
  }
}
```

| 字段 | 说明 |
| --- | --- |
| `status` | `require_confirmation=true` → `draft`（待确认）；`false` → `pending`（可直接执行） |
| `manager_recommendation` | `auto_select` 模式下为 Manager 推荐结果对象，`manual` 为 `null` |
| `available_agents` | 系统可用智能体列表（前端选择器数据源） |
| `task` | 完整任务对象（含生成的 `steps`，顺序 = `selected_agents` 顺序） |

错误：缺 `topic` → `topic (或 title) is required`；缺 members → `agent_group_config.members is required`；非法类型 → `非法 task_type: xxx（可选 [...]）`

周期任务示例：

```bash
curl -X POST http://172.20.51.153:6789/api/v2/tasks \
  -H "Content-Type: application/json" -H "X-User-Id: admin" \
  -d '{
    "topic": "每周运维报告", "task_type": "periodic",
    "execution_mode": "manual", "selected_agents": ["dfecrab"],
    "agent_group_config": {"members": [{"agent_id": "dfecrab", "role": "analyst"}]},
    "schedule": {"cron": "0 9 * * 1", "timezone": "Asia/Shanghai"}
  }'
```

### 3.4 删除任务

`DELETE /api/v2/tasks/{task_id}`

```json
{ "success": true, "data": { "task_id": "task_..." }, "message": "任务 task_... 已删除" }
```

> 同步清理：定时作业（如有）、审计文件。不存在 → `success:false`（可安全重试）。

### 3.5 转化任务类型

`POST /api/v2/tasks/{task_id}/convert` — body `{ "target_type": "periodic", "schedule": {"cron": "0 8 * * *"} }`

```json
{
  "success": true,
  "data": {
    "original_task_id": "task_a",
    "new_task_id": "task_b",
    "new_task_type": "periodic",
    "task": { ... }
  }
}
```

> 行为：新建目标类型任务（复制主题/描述/智能体配置），**原任务置为 `converted`**；转化为周期类型且给了 `schedule` 时，确认后自动注册调度。
> `target_type` 与原类型相同 → 直接返回原任务（不新建）。

### 3.6 审批（确认/拒绝）

`POST /api/v2/tasks/{task_id}/approve` — body `{ "approved": true, "approved_by": "admin", "modified_config": {} }`

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `approved` | **是**（布尔） | `true`=确认，`false`=拒绝（任务置 `cancelled`） |
| `approved_by` | 否 | 操作人，默认 `system` |
| `modified_config` | 否 | 确认时调整配置（如 agents） |

```json
{ "success": true, "data": { "task_id": "task_...", "status": "pending", "message": "任务已确认" } }
```

> 确认后：`draft → pending`；若是周期任务且带 `schedule` → **自动注册到调度器**（可在 `/api/tasks/scheduled` 看到 `next_run`）。
> `approved` 非布尔 → `body 需含布尔字段 approved`。

### 3.7 / 3.8 暂停 / 恢复（定时任务）

`POST /api/v2/tasks/{task_id}/pause`　`POST /api/v2/tasks/{task_id}/resume`

```json
// pause
{ "success": true, "data": { "task_id": "task_...", "status": "paused", "next_run": null }, "message": "任务已暂停" }
// resume
{ "success": true, "data": { "task_id": "task_...", "status": "pending", "next_run": "2026-09-21T09:00:00+08:00" }, "message": "任务已恢复" }
```

> 仅对**已在调度器中**的任务有效；否则 → `任务不在调度器中（可能未确认或非定时任务）: xxx`

### 3.9 / 3.10 手动触发 / 执行

`POST /api/v2/tasks/{task_id}/trigger`　`POST /api/v2/tasks/{task_id}/execute`（同一执行引擎）

body：`{ "user_input": "可选输入", "background": false }`

| 场景 | 响应 |
| --- | --- |
| 同步执行完成 | `{"success": true, "data": {"task_id": "...", "status": "completed", "progress": 100.0}}` |
| 后台执行（`background: true`） | `{"success": true, "data": {"task_id": "...", "status": "running", "background": true}}` |
| 未确认（draft） | `{"success": false, "error": "任务尚未确认（draft），请先调用 /approve"}` |
| 执行中重复触发 | `{"success": false, "error": "任务正在执行中: xxx"}` |

> 执行过程中步骤状态/审计实时落库，可用 `/progress`、`/audit`、`/dashboard` 观测。

## 五、常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 任务列表为空 | 任务目录不对 | 确认网关工作目录下存在 `data/tasks/`；或用 `DFECRAB_TASKS_DIR` 指定 |
| `execute` 一直 `任务正在执行中` | 上次执行异常未收尾 | 手工把任务状态改回（`DELETE` 重建），或重启网关（内存态复位） |
| `preview` 很慢 | 走 Manager LLM 推荐 | 前端加 loading；测试时用 `execution_mode:"manual"` 绕开 |
| 周期任务没触发 | cron 写错 / 服务被暂停 | 看 `/api/tasks/scheduled` 的 `enabled`、`next_run`、`last_error` |
| 定时任务触发报错 | 回调失败 | `last_error` 有具体原因；修复后 `resume` 会重算 `next_run` |
| 审计为空 | 任务从未产生动作 | 正常；确认任务 ID 正确（审计按 task_id 一文件） |
